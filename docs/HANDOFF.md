## 2. Cara melanjutkan

1. `npm install`, salin `.env.example` ke `.env` dan isi `ANTHROPIC_MODEL` (nilai apa saja cukup untuk dev tanpa Claude); `ANTHROPIC_API_KEY` boleh kosong sampai Claude dipanggil.
2. `npm run verify` harus hijau sebelum menyentuh apa pun.
3. Pilih task dari bagian 6, kerjakan sesuai kartu di backlog, **tulis test yang membuktikan tiap AC**, lalu `npm run verify`.
4. Centang AC di backlog hanya setelah terbukti (test otomatis atau dijalankan sungguhan). Cara mencentang ada di bagian 8.
5. Perbarui `docs/README.md` bila perintah atau variabel env berubah; perbarui file ini di akhir sesi.
6. Jangan commit atau membuat PR kecuali diminta. Konvensi backlog: pesan `CC-0xx: <judul task>`.

Aturan kerja backlog (10 butir) tetap berlaku. Yang sering terlupa: tanpa panggilan Claude di unit test, kontrak API hanya berubah lewat `packages/shared`, tanpa string UI hardcode di layar produk, tanpa tabel SQLite baru, angka konfigurasi dibaca dari `config.ts`.

Peta modul server yang berguna:

- `bootstrap.ts` `startApp(config, {logger, webDist?})`: siapkan workspace, buka `app.db`, migrasi, buat runner, `listen`. `AppContext` (`config, logger, db, workspace, runner, git`) adalah tempat menambah dependensi baru. **Pemulihan check (CC-063) harus disisipkan antara `migrate` dan `listen`.**
- `http/app.ts` `createApp({logger, webDist?, registerRoutes?})`: rute `/api` baru didaftarkan lewat `registerRoutes(api)`. Pakai `validated({body, query, params}, handler)` dari `http/validate.ts` (handler menerima input hasil parse zod) dan `HttpError(status, code, message, details)` untuk galat. Semua respons non-2xx berbentuk `{ error: { code, message, details } }`.
- `proc/run-command.ts` `createCommandRunner({oasdiffBin, shellRoot})`: satu-satunya pintu ke child process. Mengembalikan `{exitCode, stdout, stderr}` untuk exit code berapa pun; melempar error bertipe untuk tidak diizinkan, tidak ditemukan, timeout, abort, keluaran terlalu besar. `assertSuccess()` untuk yang menganggap exit != 0 sebagai gagal.
- `git/adapter.ts` `createGitAdapter(runner)`: seluruh operasi git read-only sebagai nilai bertipe (lihat D-19); error bertipe di `git/errors.ts` (`RefNotFoundError`, `PathNotFoundError`, akar `GitError` dengan `code`). Sudah ada di `AppContext.git` (CC-013).
- `git/paths.ts` `normalizeLocalPath(input, homedir?)`: path ketikan user → path kanonik atau `LocalPathError` (lihat D-20). Dipakai `repos/routes.ts` untuk `repos.local_path` (lihat D-22).
- `projects/` `projectRoutes(ctx)` → `(api: Router) => void` (CC-012, lihat D-21), `createProjectRepository(db)`, `slugify`. Dipasang di `bootstrap.ts` lewat `registerRoutes`; **`registerRoutes` hanya menerima satu fungsi**, jadi `bootstrap.ts` menggabungkan daftar `[projectRoutes(context), repoRoutes(context)]`. Fitur berikutnya cukup menambah satu entri di daftar itu.
- `repos/` `repoRoutes(ctx)` (CC-013, lihat D-22) dan `createRepoRepository(db)`. Memakai `AppContext.git` untuk validasi saat simpan.
- `workspace/layout.ts` `WorkspaceLayout` (hanya menghitung path, selalu di dalam root) dan `workspace/store.ts` `WorkspaceStore` (I/O: tulis atomic, baca cache, hapus data project atau repo).
- `shared/src`: `domain.ts` (enum), `api.ts` (amplop galat, `ERROR_CODES`, `ValidationDetails`, `HealthResponse`), `projects.ts` (CC-012), `repos.ts` (CC-013). **Skema endpoint lain belum ada**, lihat G-2.
- `fixtures/make-fixtures.ts` `makeFixtures(dir)` mengembalikan `{root, repos}`; tiap repo: `{name, role, path, remote, defaultBranch, specPath?, specCmd?, commits}` (`commits` = SHA per label: svc-order `initial`, `feature-xyz`, `readme`; repo lain `initial`). `path` adalah nilai `local_path` untuk mendaftarkan repo. Isi repo ada sebagai berkas biasa di `fixtures/repos/<repo>/<NN-langkah>/` (satu langkah satu commit, disalin menimpa pohon kerja); berkas spec dan skrip `spec_cmd` dibangkitkan dari `fixtures/specs.ts`. Satu generasi ~2,5 dtk di Windows, jadi test task lain sebaiknya membangkitkan sekali per berkas test (atau lewat `globalSetup`), bukan per test.

## 7. Hal teknis yang menjebak

- **Windows**: `rename` yang menimpa file yang sedang dibuka proses lain gagal `EPERM`; `WorkspaceStore` mengulang sampai 10 kali. Biner yang hilang **tidak** dilaporkan sebagai `ENOENT` oleh execa di Windows (exit 1 + pesan cmd.exe sesuai bahasa OS), karena itu `proc/executable.ts` mencari di `PATH`/`PATHEXT` sendiri sebelum menjalankan.
- **Express 5**: callback `app.listen` menerima galat (mis. `EADDRINUSE`); `req.query` hanya-baca; handler async yang ditolak otomatis diteruskan ke error handler.
- **Vitest**: konfigurasi per paket (`projects`); server/web butuh `resolve.conditions: ['source']` agar `@cc/shared` terbaca dari sumber. Di env jsdom `import.meta.url` bukan URL `file:`; pakai `import.meta.dirname`. Jalankan satu paket: `npx vitest run --project server`.
- **`@cc/shared`** diekspor dengan kondisi `source` (dev/test/typecheck membaca `src`) dan `default` ke `dist` (runtime produksi). `npm run build` membangun `shared` lebih dulu; jangan mengubah urutannya.
- **Jangan menghentikan proses berdasarkan pola nama** (`vite`, `tsx`, `node`): milik proses lain bisa ikut. Hentikan lewat PID atau port yang Anda mulai sendiri. Proses uji yang ditinggalkan `timeout` di Git Bash tidak ikut mati.
- **Fixture git** (CC-090): jangan menjalankan `git` dari test dengan env mentah; pakai `gitEnv`/`git()` di `make-fixtures.ts` untuk apa pun yang menulis. Git objects bersifat read-only di Windows; hapus folder fixture dengan `fs.rm(..., {recursive, force, maxRetries})`. Mesin ini punya Python 3.12 dan Go 1.24 (bukan syarat; test tidak memakainya), tetapi tidak punya `oasdiff`. Isi Go dan Python fixture sudah dicek satu kali dengan `gofmt -l`, `go vet`, dan `py_compile`, bukan oleh test.
- **`guardrails.test.ts` memindai teks, bukan hanya pemanggilan**: kata polos seperti `commit` (juga dalam backtick di komentar) di berkas yang memanggil git ditandai sebagai perintah penulis. Tulis ulang redaksinya; jangan melonggarkan guardrail. Kata `commit` dalam `^{commit}` (di `adapter.ts`) lolos karena tidak berdiri sendiri di dalam tanda kutip.
- **`better-sqlite3`** native: npm 11 menampilkan peringatan `allow-scripts`, tetapi binding terpasang normal di mesin ini dan di Docker. Jika di mesin baru muncul "Could not locate the bindings file", jalankan `npm rebuild better-sqlite3`.
- Verifikasi Node 20 (dari root repo, Git Bash). Langkah yang sama (`npm ci` -> `verify` -> `build`, lewat skrip `sh` terpisah) sudah lolos dua kali di `node:20` v20.20.2, terakhir dengan 314 test.
